给 agent 更长的上下文窗口，不等于给它记忆。那只是给了它一张更大的桌子。

## 反复发现的问题

每个新会话开始，编码 agent 都会重新读同样的文件、重新追踪同样的调用链、重新理解同样的决策。这些工作消耗 token 和注意力，而且什么都不会留到下一个会话。

LadyM 改为缓存工作区的「理解」：代码分析、决策、技能与历史事件。agent 用一个关键词就能回忆。读取路径是启发式的，因此召回快且可预测——热路径上没有模型调用。

## 一个存储，一个激活函数

最独特的设计在 L2：tree-sitter 提取的代码符号与普通事实放在同一个存储里，由同一个 ACT-R 激活函数打分。记忆与代码库检索不是两套需要对齐的系统，而是一套系统。

L0 到 L4 分别对应工作记忆、情景记忆、语义记忆、程序记忆与联想记忆。后台 worker 异步提炼 L5 心智模型与 L6 前向意图，并通过 supersedes 链让记忆演进，而不是不断堆积。

## 本地优先，agent 就绪

二进制是单个静态 Go 可执行文件，不使用 cgo。SQLite、进程内向量索引与纯 Go 的 tree-sitter 运行时，意味着无需网络、无需下载模型、无需 API key 就能开始。

任何 MCP 客户端都能接入：

```json
{
  "mcpServers": {
    "ladym": {
      "command": "ladym",
      "args": ["serve", "--db", "/absolute/path/to/ladym.db"]
    }
  }
}
```

同一套引擎还提供 CLI、Go SDK 与 Claude Code 技能。一个引擎，多种前端。
