一份无视现有系统的需求文档不是计划，而是一张愿望清单。

Porto 为了解决一个具体问题而诞生：PRD 进去，通用套话出来，工程团队在下一个迭代里重新切分模块。规格看起来很完整，但它没有指向任何一个真实存在的模块。

## 让规格建立在真实之上

Porto 从 SCV 构建的知识库中检索上下文。SCV 读取代码库，产出四份文档：定位与快速开始的 README、五分钟摘要、带架构图的架构文档，以及逐文件的职责索引。

这些文档描述的是真实存在的系统、模块与 API。Porto 生成子系统规格时，可以引用它们。于是结果会写「扩展现有账本服务」，而不是「新增一个账本服务」。

## 让质量可观察

每份规格都经过生成、评判与精化的循环，并按十二项标准打分。模板级输出的分值从大约 3.2 提升到 11.4。每一次检索、工具调用与返工决策都被记录，评审者能看到规格为什么这么写。

如果模型不可用，确定性回退会让流程继续运行。模型是质量放大器，不是开关。

## 无需密钥即可试用

两个项目都能在本地运行。克隆 SCV，执行 `./install.sh`，然后把 Porto 指向生成的知识库。完整流程不需要 API key；加上 key 只会提升文字质量，不会改变可用性。
